# v1.6.00 Enhancement Log

**Release date:** 2026-09-01
**Progress Tracker:** `Completed — implemented and verified offline. NOT deployed.` Same discipline
as v1.5.01: unit + app suites green against the recorded baseline, full-bundle `validate` proven OK
(see §4c for the one deliberate, documented exception), no `bundle deploy` run — see §4d.

**Theme:** three contracts made honest. (1) *The Intermediate Object Rule*: an intermediate dataset
is a `@dlt.view` or a pipeline-scoped temporary table, never a published one — what used to leak
`_staged`/`_src__*`/`recon__*` plumbing into Unity Catalog now leaves only final sinks visible.
(2) *`logging_config` means what it says*: reconciliation's capture flags now gate dataset
registration and `reconciliation_result`, not just two of three log tables — both flags off means
business targets only. (3) *The UI means what it exports*: the Spec Builder had ~29 display-only
defaults whose values never reached the JSON payload; every default is gone, so an untouched field
is empty/OFF on screen and absent in the export. Plus: CSV staging for encrypted ZIP exports, a
five-job `metaflow_sample` reference suite, wheel artifacts on a UC Volume, and two new doc pages.

**The load-bearing finding.** "Convert all intermediates to views" — the refactor as first stated —
is wrong against this framework's own hard-won rules: a `@dlt.view` is inlined per consumer, so a
multi-reader view re-opens the exact read-once (R2) bug the materialization exists to fix, and two
constructs (`_scd2_history`, `_snapshot_input`) cannot be views at all. The correct invariant is
*"intermediates are never **published**"*: views where single-reader (already the default),
`@dlt.table(temporary=True)` where materialization is mandatory, and a short, documented exception
list where Lakeflow's API forces publication (see E36/E38). Every exception is stated in code
comments, docs 07/13, and `common_pitfalls.md` 35 — because the blanket slogan is exactly the kind
of rule a future refactor would "enforce" into a regression.

## 2. Previous State vs. Current (Target) State

### E36–E38 — intermediates were published tables

- **Previous:** `register_staged_view(materialize=True)` published `catalog.schema._<t>_staged`;
  every shared L0 node published into `source_plane.catalog`-or-the-pipeline's-own schema; recon
  registered `_recon__*__src`/`__tgt`, published `recon__*__classified`, and `_recon__*__missing`/
  pulse under `publish_schema` — all durable UC tables maintained by the pipeline.
- **Current:** all of the above are `@dlt.table(temporary=True)` under bare names — materialized
  once per update (R2 intact) and invisible in UC. Publish opt-ins/exceptions: `source_plane.
  catalog`+`schema` both set (L0), a healing flow's `_src`/healing `_tgt` (L5 `spark.read.table`),
  `__metrics`/`__mismatch` (they feed the control-table sinks — see E39), `_<t>_snapshot_input`
  (stable versioned relation for `apply_changes_from_snapshot`), `_<t>_scd2_history`
  (`create_streaming_table` has no `temporary` parameter), SCD2 `_current` and quarantine tables
  (final deliverables).
- **Why the ordering edge moved:** the heal `@dlt.append_flow` used to join the pulse against
  `__metrics` (one row by construction). `__metrics` is now conditional, and a healing flow with
  logging suppressed must still heal — so the edge anchors on the always-registered `__classified`
  and derives its own one-row gate via a `groupBy`-less `.agg()`, preserving the exactly-one-row
  guarantee an INNER stream-static join needs.

### E39–E41 — `logging_config` gated writes but not existence, and never `reconciliation_result`

- **Previous:** `run_log_capture`/`mismatch_log_capture` gated only the run-log/mismatch-log row
  writes; `__metrics`/`__mismatch` were always registered; `reconciliation_result` was written
  unconditionally, by design ("a silenced flow still leaves a record").
- **Current:** each flag gates its dataset's registration *and* its control-table writes;
  `run_log_capture` additionally gates `reconciliation_result`. Both flags false ⇒ business targets
  only. This is a **deliberate behavior change** per the release directive ("if both are false, the
  reconciliation job must bypass metric/log table creation and write actions entirely"); the
  failure signal for a suppressed-logging flow is the job/pipeline run state + structured logs.
  The two configurations that would silently contradict themselves are rejected twice (validator +
  graph definition, the latter catching pipeline-conf overrides).

### E42 — the pgp_zip sink staged JSON-Lines only

- **Previous:** hardcoded `.json` staging; "export CSVs in a password-protected ZIP" had no
  spec-level expression (the `post_export_archive.secret` passkey existed but was exercised by no
  spec in the repo).
- **Current:** `staged_file_format: "csv"` stages RFC-4180 with a header row ordered by the sink's
  write schema (`streamWriter(schema, …)` now threads it through); nested values stage as JSON
  text; `None` as an empty cell. Absent = `json`, byte-identical to pre-v1.6.0. Sample Job 4 is
  the first spec to exercise both the CSV staging and the AES passkey together.

### E43 — the app displayed defaults it never exported

- **Previous:** ~29 display-only defaults (`fval()` injected them at render; `buildFlowObject`
  iterated only stored keys) — a fresh flow *showed* `storage_format: delta`, `mode: GCM`,
  `capture_technical_metadata: ON`, `generate_hash_columns: ON`, `cdc_load_strategy: APPEND`
  while exporting none of them; the server's run path could re-inject a *different* default set
  from `config/registry/*.json`.
- **Current:** no default anywhere in either registry; empty/OFF on screen ⇔ absent in JSON; the
  framework's own defaults (documented per attribute) apply to absent keys exactly as before.
  Locked by `databricks-app/tests/test_no_registry_defaults.py` (incl. a check that the shipped
  dist bundle contains the new field and no display defaults).

### E44 — no sample/reference corpus existed

Greenfield `metaflow_sample` schema; per-job details in `resources/sample_jobs/*_job.yml` headers
and `metaflow_testing/README.md`. Two never-exercised framework capabilities gain first coverage:
`post_export_archive.secret` (Job 4) and `source_zip_handling.pre_extraction_decryption.
secret_passphrase` (Job 5), sharing one UC secret `metaflow.metaflow_sample.sample_zip_passkey`
(documented one-time manual prerequisite; seeds preflight it and fail fast). FULL_SNAPSHOT_CDC
iterations are additive-only per the documented `apply_changes_from_snapshot` accumulation
limitation.

### E45 — the wheel lived in the workspace `.internal`, and the docs disagreed with reality

- **Previous:** no `artifact_path` (the 2026-08-30 revert); three docs still claimed a UC-Volume
  path or a `framework_wheel_path` variable that no longer existed; TESTING_PLAN §0 claimed the
  Volume "fixed structurally" the mid-run-deploy kill (false — Volumes prune identically).
- **Current:** fixed shared `/Volumes/${var.catalog}/config/wheels` per target, bundle-managed
  volume, all 93 `../../dist/*.whl` references untouched (DABs rewrites at deploy). The
  **never-deploy-mid-run rule is unchanged and restated prominently** — pruning happens on Volumes
  too. Known CLI contract (v1.13.0, discovered live): `validate`/`deploy` **refuse** an
  `artifact_path` inside a not-yet-deployed Volume — the one-time bootstrap (mask `artifact_path`,
  `deploy --select volumes.framework_wheels_volume`, restore) is documented in `databricks.yml`,
  the volume file header, `docs/onboarding/04_deploying.md` and `docs/09`.

### 4c. The one failing check, by design

Unmasked `bundle validate` fails with `Error: volume metaflow.config.wheels does not exist … Please
first deploy the volume` — CLI v1.13.0 refuses an `artifact_path` inside a bundle-managed Volume
that has not had its bootstrap deploy. The premise "DABs creates the volume before uploading
artifacts" is **false on this CLI** (discovered live during this release; the wording was corrected
in every doc before it shipped anywhere). Validate goes permanently green after the documented
one-time bootstrap.

### 4d. Deliberately NOT run

- **No `bundle deploy`** (and therefore no volume bootstrap, no app `bundle run`, no live pipeline
  run). Binding reason, as in v1.5.01: a deploy prunes `<artifact_path>/.internal/` and kills any
  in-flight update; whether a wave is running is not knowable from here. Additional reason: the
  first v1.6.0 deploy over the existing `dev_metaflow` state triggers the O7 migration (renamed/
  unpublished intermediates, streaming-state resets) and should be an operator decision per
  pipeline.
- **No live verification of `temporary=True` semantics** on DBR — see §6.

## 6. Known Gaps

1. **Not deployed; `temporary=True` semantics not live-verified.** Everything here is offline
   verification (unit suites, AST guards, masked `bundle validate`). The specific behaviors that
   only a real update can prove: `@dlt.table(temporary=True)` on serverless UC pipelines for the
   staged/plane/recon nodes; the heal handler's `spark.read.table` of the still-published `_src`/
   `_tgt` under the new mixed surface; the O7 migration behavior on a pipeline with history. The
   first live run should be the sample suite (born on v1.6.0, no migration surface), then one
   disposable pre-existing pipeline before anything that matters.
2. **The one-time volume bootstrap is documented, not executed** — `bundle validate` fails with the
   volume-does-not-exist error until an operator runs it (§4c).
3. **The `metaflow_sample` UC secret is a manual prerequisite** (`metaflow.metaflow_sample.
   sample_zip_passkey`) — Jobs 4/5 fail fast at seed time with a clear message until it exists.
4. **Sample Job 1's observability destination has no export task** — its spec onboards a
   DATABRICKS_VOLUME destination, but only Job 3 carries the `observability_export` task; Job 1's
   header notes the 6-parameter wiring to copy if wanted.
5. **`docs/site` / `databricks-app/docs_site` regeneration** happens at the end of this release's
   verification pass (`mkdocs build`, `scripts/build_app_docs.py`); if either is skipped the
   served wiki lags the markdown — check `git status` for `site/` before trusting the rendered
   pages.
6. **App UI completion meters recalibrated** — removing display defaults changes `reqStats`
   percentages and the CDC card starts unselected; deliberate, but user-visible on first load.
