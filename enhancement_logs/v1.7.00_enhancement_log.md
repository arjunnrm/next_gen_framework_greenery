**Release date:** 2026-09-02
**Progress Tracker:** `Completed — implemented and validated. Six sample jobs reduced to exactly two
tasks each; all provisioning consolidated into flowx_sample_seed_job; the six onboarding specs
moved into the bundle at resources/sample_jobs/onboarding/. bundle validate OK on target arjun.
Unit suite back to the exact pre-change failure baseline (9 failed / 113 errors) with +2 net new
passing tests. NOT yet deployed or run live — see §6.`

**Theme:** the sample suite becomes a *developer blueprint*.

A sample job is a pattern developers clone. Every task in it that is not the pattern is a task the
developer must first understand and then delete. Before this release each sample job carried four
tasks — `setup_control_tables -> onboard_sample_NN -> run_pipeline -> store_sample_config` — of which
exactly one was the thing being demonstrated. The suite now reads:

```
SAMPLE JOB (the blueprint, x6)        SEED JOB (provisioning, run once)
  pipeline_task                         provision_sample_schema
  observability_task                      -> setup_control_tables
                                             -> onboard_all_samples
                                                  -> 6 parallel seed chains (3 iterations each)
```

**The load-bearing finding.** "Exactly two tasks" and "a reproducible reference pattern" are in
direct conflict if onboarding is simply deleted. `pipeline_task` resolves its configuration from the
control tables, and a group that was never onboarded fails at
`control_plane/repository.py:79` with

    FrameworkConfigError: No active dataflow_group_spec row found for dataflow_group_id='...'

The resolution is that onboarding is **provisioning**, the same category as seeding — so it moves to
the seed job rather than disappearing. One `onboard_all_samples` task now onboards all six specs in
a single run by pointing the generic `framework_config_onboarding_job` at the bundle's spec
directory, replacing six per-job tasks. Delegation is still via `run_job_task`, never an inline
`02_onboarding_engine.py` (AGENTS.md).

## 6. Known Gaps

- **Sample jobs are no longer standalone.** This is the deliberate cost of the 2-task rule: a
  developer who runs a sample job without having run `flowx_sample_seed_job` gets
  `FrameworkConfigError: No active dataflow_group_spec row found`. Every sample job header and both
  docs state the prerequisite, but nothing *enforces* it — Lakeflow has no cross-job precondition.
- **`store_sample_config` is gone, and with it the sample-config Volume publication.**
  `/Volumes/<catalog>/flowx_sample/sample_configs/` is no longer populated. The specs are now in
  the bundle at `resources/sample_jobs/onboarding/`, which is arguably a better home for a developer
  reading them — but anything that consumed that Volume must be repointed.
  `notebooks/09_sample_reference/09a_store_sample_config.py` is now **orphaned** (no resource
  references it); it was left in place rather than deleted, pending a decision.
- **Not deployed or run live.** All verification above is static (YAML parse, unit tests, `bundle
  validate`). The suite has not been deployed to a workspace or executed end-to-end in this release
  — and per the standing rule, a deploy must not be issued while any pipeline or test wave is
  running.
- **`action_type` is a seed-job parameter, not automatic.** Re-onboarding a changed spec needs an
  explicit `--params action_type=UPDATE`; a plain re-run uses `CREATE`.
