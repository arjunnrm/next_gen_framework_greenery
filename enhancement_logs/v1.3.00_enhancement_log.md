## 2. Previous State vs. Current (Target) State

### E01 — Landing retention policy
- **Previous:** `landing_retention_policy.clean_source = "archive"` with a missing/empty `archive_path` raised a hard `FrameworkConfigError` at validation time. `retention_days` had an implicit minimum of 1.
- **Current:** `archive` with a missing or empty `archive_path` **degrades to `off`** with a runtime WARNING log — not a validation error. `delete` never requires `archive_path`. `retention_days: 0` passes schema validation (minimum is 0). Default `retention_days` when omitted is 7. Applies exclusively to the Auto Loader `cloudFiles.cleanSource*` options — never to the raw ZIP/archive pre-extraction path (unchanged, reconfirmed).

### E02 — ZIP source deletion
- **Previous:** `source_zip_handling.delete_source_after_extract` was a plain boolean only (`true` = delete after extract, `false`/omitted = never).
- **Current:** Accepts a nested object — `{"action": "delete_now"}` (equivalent to legacy `true`) or `{"action": "delete_after_x_days", "days": N}` — normalized internally via `resolve_zip_delete_policy`. The legacy boolean is still accepted for backward compatibility (every existing spec keeps working unchanged). `delete_after_x_days` runs an age-based sweep (`sweep_aged_archives`) of the landing directory at extraction time, excluding **only archives whose extraction failed in the same run** — corrected during remediation (see §6) from an earlier draft that excluded every matched archive, which made the sweep provably inert.

### E03 — JSON explode / auto-flatten
- **Previous:** `apply_explode_columns(df, explode_columns, auto_flatten_all=False)` treated an empty list and an absent key identically — both left `df` unchanged.
- **Current:** An **explicitly-present but empty** `explode_columns: []` now auto-flattens every nested struct and explodes every array in the schema. An **entirely absent** `explode_columns` key remains schema-preserving pass-through — this distinction is load-bearing (a prior regression caused silent cartesian row explosion on un-configured sources) and is resolved at the call site via key presence, not `.get()` truthiness. Parquet sources gain parity: named JSON-string columns are parsed via `from_json`/`schema_of_json` before the same flatten treatment applies to the resulting struct.

### E04 — Stream-level deduplication
- **Previous:** No framework-level dedup option; a spec author had to hand-write `dropDuplicates()` outside the framework.
- **Current:** `source_config.remove_dups` (bool, default `false`). When `true`, applies full-row deduplication over the streaming DataFrame across every column present at that point in the ingestion chain **excluding** `__framework_*` technical columns and `_rescued_data` (new `ingestion/dedup.py` module). Documented operational caveat: without a watermark this holds unbounded dedup state.

### E05 — Column normalization case sensitivity
- **Previous:** `normalize_column_names` (bool) unconditionally lowercased.
- **Current:** New `source_config.column_normalization` object (`{"enabled": bool, "case": "lower"|"preserve"|"upper"}`) layers on top of the legacy boolean. Precedence: an explicit `column_normalization.enabled` wins; when the object is present but **omits** `enabled`, the legacy `normalize_column_names` boolean still governs (fixed during remediation — see §6, this previously silently disabled normalization for any operator who added the object without also repeating `enabled: true`).

### E06 — Partitioning fallback
- **Previous:** Behavior of `target_config.partition_columns: []` versus an omitted field was not explicitly distinguished at the writer layer.
- **Current:** An explicit empty array configures the target Delta table with **no partitioning** — never treated as an error, and never silently collapsed into a zero-argument `partitionBy()` call that could be misread as "omitted."

### E07 — Liquid clustering limit
- **Previous:** No upper bound on `target_config.liquid_clustering_columns`.
- **Current:** A maximum of 3 columns, enforced both at onboarding-time schema/validator level (`onboarding/spec_validator.py`, `onboarding_spec.schema.json` `maxItems: 3`) and defense-in-depth at runtime in `storage/table_properties.py` and `dq/quarantine.py`.

### E08 — Deterministic hashing standard (BREAKING)
- **Previous:** `cdc/hashing.py` computed `sha2(concat_ws('||', coalesce(cast(col as string), ' NULL ')), 256)` — no trim/lower normalization. `crypto/hashing.py`'s surrogate-key generator used an equivalent but separately-maintained construction.
- **Current:** Every participating column is normalized as `trim(lower(cast(col as string)))` before hashing, with a collision-safe null sentinel, before joining with `||` and hashing with `sha2(..., 256)`. **One** canonical expression-building function now backs `__framework_hash_key`, `__framework_hash_value` (`cdc/hashing.py`) and `__framework_surrogate_key` (`crypto/hashing.py`) — the latter imports from the former rather than duplicating the construction. **This is a breaking change**: every already-materialized CDC target's hash columns will not match newly-computed digests until that target is fully refreshed, and reconciliation batch fingerprints change on first post-upgrade run (a one-time re-append of previously-`SUCCESS`-logged batches, not a bug). See `docs/11_hashing_and_determinism.md` for the reproducible SQL snippet and full migration note.

### E09 — CDC truncate-and-load empty-source guard
- **Previous:** A `TRUNCATE_AND_LOAD` flow whose source recomputed to zero rows always blanked the target table.
- **Current: WITHDRAWN (2026-08-29), option accepted but not enforced.** The intended behavior was `target_config.empty_target_if_source_empty` (bool, default `false`): an empty source would leave the target untouched. Implemented as `cdc/dispatcher.py::resolve_truncate_and_load_source` and called from `dq/quarantine.py::_clean_upstream`'s non-CDC branch — which live execution proved unworkable. Preserving the target means recomputing it from its own previous contents, i.e. the dataset reads itself, and Lakeflow aborts graph construction with `Graph is not topologically sorted. There is a cycle between <target> and <target>`. `TC-CDC-002` failed before a single flow ran. The eager emptiness check is independently unusable: `_clean_upstream` is evaluated during graph *construction*, when an upstream produced by the same update legitimately holds no data, so "empty source" and "not yet materialized" are indistinguishable. The call site is removed; `resolve_truncate_and_load_source` is retained, unwired and annotated, because the policy is still wanted — but it must be evaluated **outside** the pipeline graph (a post-update row-count check in the style of `reconciliation/`).

### E10 — Snapshot CDC internal surrogate key
- **Previous:** `FULL_SNAPSHOT_CDC_NO_PK` required the operator to explicitly configure surrogate-key generation; `generate_surrogate_key: false` on that strategy raised `CdcStrategyError`.
- **Current:** The framework forces surrogate-key generation on for `FULL_SNAPSHOT_CDC_NO_PK` regardless of an explicit `false`, emitting a WARNING rather than failing — removing the hard requirement while preserving an explicit opt-out's intent as diagnostic-only. New optional `target_config.surrogate_key_columns` / `surrogate_key_exclude_columns` pin the hash's basis; both are threaded through to `crypto/hashing.py::generate_surrogate_key_hash`.

### E11 — Hierarchical Spark configuration
- **Previous:** No documented precedence between framework-wide Spark defaults and pipeline/runtime-level overrides.
- **Current:** New `engine/spark_config.py`: pipeline/runtime values strictly override framework built-in defaults. Canonical acceptance case verified: a framework default of `spark.sql.shuffle.partitions = 200` is overridden to `auto` when the pipeline configuration specifies it.

### E12 — Reconciliation
- **Previous:** `recon_mode` (`triggered`/`continuous`) and `logging_config.run_log_capture`/`mismatch_log_capture` already existed per-flow; two-tier hash-first verification existed in `matcher.py` as a full-dataset join, not a cheap early-out fingerprint; reconciliation scope was not restricted to Delta tables (a `type: "file"` source validated for `path`/`format`).
- **Current:** (a) `triggered` mode reads `task_run_id` as a dynamic job parameter to bound a reconciliation to one pipeline run; `continuous` mode runs `reconciliation/streaming.py` as a decoupled streaming process. (b) New runtime parameters `recon_run_log_capture` / `recon_mismatch_log` override the per-flow `logging_config` values when supplied. (c) A genuine Phase 1 cheap aggregate fingerprint (`bit_xor(hash)` + count per side) now runs before the existing full `matcher.py` join, which becomes Phase 2 and only executes on a Phase 1 mismatch — `matcher.py`'s duplicate-key-safety collapse (see its module docstring) is preserved unchanged as the Phase 2 engine. (d) Reconciliation is now validated as **Delta tables only** — a `source_config.type` other than `"table"` is rejected outright with an explanatory error, rather than validated for file-specific fields.

### E13 — Observability
- **Previous:** Triggered (batch, post-pipeline) event-log extraction existed (`08_dlt_observability_engine.py`); a separate always-on continuous streaming design existed for `event_log`. Neither read an explicit *array* of event-log tables for the continuous case.
- **Current:** Triggered mode reads task parameters from the orchestration context and filters `event_log` by `start_time`/`end_time` bounded by `task_id` (confirmed pre-existing machinery, extended per contract). Continuous mode accepts an array of fully-qualified `catalog.schema.event_log_table` names, streams all configured tables together, and emits to Databricks Volumes or OTel endpoints — all of this module's pre-existing deliberate design decisions (per-flow `Resource`, `(update_id, flow_id)`-keyed `FlowMetrics`, deterministic volume file naming, the `env:`/`secret:` credential syntax, `DATABRICKS_VOLUME` destination type) were preserved unchanged.

### New — Generic bulk config-onboarding job
- **Previous:** Onboarding a directory of specs required one `bundle run onboarding_job` invocation per spec file.
- **Current:** `framework_config_onboarding_job` (deployed resource) + `onboarding/bulk_onboarding.py` + `notebooks/02_onboarding/02b_bulk_config_onboarding_engine.py`: onboards every spec in a directory in one run, fail-soft by default (every spec attempted even after one fails; the run raises at the end summarizing all failures), with an optional `fail_fast=true` for gating CI use. Generic — not test-specific; `metaflow_testing/` is simply its default `spec_dir`. Tagged `purpose: testing` for cost/usage separation. **Live-run result: 43/43 specs succeeded** (see §4).

## 6. Defects Found and Fixed (adversarial verification pass)

Two **critical** and two **major** defects were found by independent verifiers reading the implemented code against the frozen contract, and all four were confirmed fixed by a second, independent re-verification pass with executed proof probes:

1. **[CRITICAL, E09]** `resolve_truncate_and_load_source` had zero callers — the entire empty-source truncate guard was dead code, meaning a `TRUNCATE_AND_LOAD` flow with a zero-row source still blanked its target. Wired into `dq/quarantine.py::_clean_upstream`'s non-CDC branch via a new `_read_existing_target_or_none` helper — and **reverted on 2026-08-29** after live execution showed the wiring makes the target read itself and fails Lakeflow graph construction with a self-cycle (TC-CDC-002). The guard is unwired again, this time deliberately and documented; see E09 above.
2. **[CRITICAL, E10]** An explicit `generate_surrogate_key: false` on `FULL_SNAPSHOT_CDC_NO_PK` still raised `CdcStrategyError` — the opposite of E10's stated goal, and `surrogate_key_columns`/`surrogate_key_exclude_columns` were read nowhere. **Fixed**: surrogate-key generation is now forced on with a WARNING (never a hard failure) for that strategy, and both column-scoping options are threaded through.
3. **[MAJOR, E02]** `delete_after_x_days`'s sweep excluded every archive matched in the current run — identical, by construction, to its own candidate set — making it provably unable to ever delete anything, while the retained archive was silently re-extracted on every subsequent update. **Fixed**: the sweep now excludes only archives whose extraction *failed* this run; successfully-extracted archives age and are swept normally.
4. **[MAJOR, E05]** A `column_normalization` object present but omitting `enabled` silently disabled normalization even when the legacy `normalize_column_names: true` was set — the most natural adoption path for an existing user. **Fixed**: absence of `enabled` now defers to the legacy boolean; only an explicit `enabled` value overrides it.

A fifth related defect (**[MAJOR, E08]**) — `crypto/hashing.py`'s `resolve_surrogate_key_columns` treated a present-but-empty `include_columns: []` the same as absent (truthiness check), silently widening a surrogate key to every column instead of the empty/scoped basis declared — was found in the same verification pass and fixed identically (test for `None`, not truthiness), per the same before/after discipline as E03's `explode_columns`.

Full before/after evidence (probe scripts, diffs against pre-fix backups, byte-level string comparisons against the contract) is preserved in the workflow transcripts; see this log's introduction for the transcript directory paths if deeper audit is needed.
