# Test Pipeline: TC-ING-004 -- ASN.1 Binary Telecom CDR Decoding

> See also: [Documentation index](README.md), [flowx_testing/TESTING_PLAN.md](../flowx_testing/TESTING_PLAN.md) (Module 1), [flowx_testing/TESTING_STATUS.md](../flowx_testing/TESTING_STATUS.md), [13_asn1_dq_quarantine.md](13_asn1_dq_quarantine.md) (the pre-existing ASN.1 + DQ/quarantine demonstration this scenario is a dedicated, `TC-*`-numbered sibling of, not a replacement for).

## Purpose

Prove `source_type: "asn1"` binary telecom CDR decoding end to end, as its own dedicated,
independently deployable test case (`TC-ING-004` in `TESTING_PLAN.md`'s Module 1), using a
brand-new GSM call-detail-record schema (`gsm_cdr.asn`) distinct from the existing
`telecom_cdr(_v2).asn` fixtures `docs/13_asn1_dq_quarantine.md` already exercises. This
scenario's fixture batch is deliberately **all-valid** -- it proves the clean-decode path
(`imsi`/`callDurationSeconds` populated, zero `_asn1_decode_error` rows), not the
decode-failure/quarantine-routing path, which `docs/13` already covers with a mixed-quality
batch.

## Responsibilities

* Decode 3 ASN.1 BER-encoded GSM CDR files against a configured schema (`gsm_cdr.asn`, a
  `SEQUENCE` of `imsi`, `imei`, `callDurationSeconds`, `cellId`, `roamingFlag`).
* Land the decoded output as a streaming Bronze table
  (`{catalog}.bronze_telecom.cdr_stream_raw`, `cdc_load_strategy: "APPEND"`).
* Apply 3 quarantine-action DQ rules (decode success, non-empty `imsi`, non-negative
  `callDurationSeconds`) as a structural safety net -- with an all-valid fixture batch, the
  expected outcome is **zero** quarantined rows, proving both the decode and the DQ rules
  agree the batch is clean.

## Inputs

* `sample_data/asn1_schema/gsm_cdr.asn` -- the real ASN.1 module file (verified locally: a
  full `asn1tools.compile_files(...)` compile + `encode`/`decode` round-trip, and the
  framework's own `asn1/decoder.py::derive_asn1_field_defs` schema-derivation, both run
  clean against it before this scenario was wired into a spec -- see below).
* 3 CDR fixtures, generated **directly on-cluster** at seed time by
  `notebooks/00_seed_sample_data/03_seed_asn1_gsm_cdr_fixture.py` (not synced as pre-built
  binary files -- Databricks Workspace Files sync can mangle a raw `.ber` upload; identical
  rationale to `docs/13_asn1_dq_quarantine.md`'s and `sample_data/generate_asn1_dq_fixtures.py`'s
  own note): `gsm_cdr_001.ber` / `gsm_cdr_002.ber` / `gsm_cdr_003.ber`, all valid.
* `flowx_testing/013_ing_004_asn1_decode.json`.

## Outputs

* `{catalog}.bronze_telecom.cdr_stream_raw` -- 3 rows, one per fixture, with `imsi`, `imei`,
  `callDurationSeconds`, `cellId`, `roamingFlag`, and `_asn1_decode_error` (`NULL` on every
  row) all populated per the ASN.1 -> Spark type mapping (`imsi`/`imei`/`cellId` ->
  `string`, `callDurationSeconds` -> `bigint`, `roamingFlag` -> `boolean`).
* `{catalog}.bronze_telecom.cdr_stream_raw_quarantine` -- created (per
  `register_main_and_quarantine_tables`'s conditional-creation rule -- see
  [17_onboarding_template_reference.md §4.7](17_onboarding_template_reference.md)) since this
  spec's `dq_config.rules` include a `quarantine`-action rule, but expected **empty** (0
  rows) for this all-valid fixture batch.

## Configuration

`flowx_testing/013_ing_004_asn1_decode.json`'s one `ingestion_flows[]` entry:

```json
"source_config": {
  "path": "/Volumes/{{catalog}}/telecom/landing_cdr/incoming/",
  "schema_location": "/Volumes/{{catalog}}/telecom/_schemas/cdr_stream_raw/",
  "file_pattern": "*.ber",
  "asn1_schema_path": "/Volumes/{{catalog}}/telecom/schemas/gsm_cdr.asn",
  "asn1_codec": "ber",
  "asn1_pdu_name": "GsmCallDetailRecord",
  "capture_technical_metadata": true
}
```

Two distinct `telecom`-schema Volumes are provisioned by the seed notebook, deliberately
named to avoid confusing one for the other:

* `{catalog}.telecom.schemas` -- holds the real `.asn` module file itself
  (`/Volumes/{catalog}/telecom/schemas/gsm_cdr.asn`), per this test case's own spec.
* `{catalog}.telecom._schemas` -- Auto Loader's `cloudFiles.schemaLocation` checkpoint state
  (`schema_location`), the same `_schemas`-named-Volume convention
  `Excalibur_usecase._schemas` already uses in scenario 002/003 -- **not** the same thing as
  the volume above, despite the similar name.

`target_config` is plain `APPEND` (a raw, append-only CDR event stream -- there is no natural
update/merge key for an individual call record, unlike a dimension-style entity), so
`generate_hash_columns`/`primary_keys` are omitted entirely (inert for `APPEND` regardless --
see [17_onboarding_template_reference.md §4.2](17_onboarding_template_reference.md)).

`dq_config.rules` (all `action: "quarantine"`, `record_id_column: "imsi"` since this schema
has no dedicated `recordId` field the way `telecom_cdr_v2.asn` does):

| `rule_id` | `expression` |
|---|---|
| `dq_asn1_decode_ok` | `_asn1_decode_error IS NULL` |
| `dq_imsi_present` | `imsi IS NOT NULL AND imsi <> ''` |
| `dq_call_duration_non_negative` | `callDurationSeconds IS NULL OR callDurationSeconds >= 0` |

(The `IS NULL OR ... >= 0` form on the duration rule -- not just `>= 0` -- is deliberate;
see `docs/13_asn1_dq_quarantine.md`'s identical callout on SQL three-valued logic for why a
bare `>= 0` would silently fail to flag a genuinely `NULL` value as a violation.)

## Main execution flow

```bash
databricks bundle deploy --target dev
databricks bundle run flowx_test_ing_004_asn1_decode_job --target dev
```

Task chain: `setup_control_tables -> seed_asn1_gsm_cdr_fixture -> onboard_ing_004 ->
run_ing_004_pipeline`.

Runtime path (`notebooks/03_engine/03_lakeflow_declarative_pipeline.py`, `read_asn1_source` ->
`asn1/decoder.py::decode_asn1_binary_stream`): Auto Loader's `binaryFile`-format `cloudFiles`
reader lists the 3 `.ber` files from `path` -> `derive_asn1_field_defs` introspects
`gsm_cdr.asn` once (via `asn1tools.parse_files`) to build the Spark output schema ->
`mapInPandas` decodes each file's raw bytes against `GsmCallDetailRecord`, one partition at a
time (the ASN.1 schema compiled once per partition, not once per row) -> the 3 quarantine
rules are evaluated per row -> `register_main_and_quarantine_tables` splits clean rows into
`cdr_stream_raw`, any DQ-rule failures into `cdr_stream_raw_quarantine`.

## Design decisions

* **A dedicated `gsm_cdr.asn` schema, not a reuse of `telecom_cdr(_v2).asn`.** The two
  existing schemas already have their own dedicated demonstration
  (`docs/13_asn1_dq_quarantine.md`) exercising the decode-failure/DQ-violation path with a
  mixed-quality 5-file batch; reusing them here would blur which scenario is proving what.
  `gsm_cdr.asn` adds `imei` and `roamingFlag` (a `BOOLEAN` field, not otherwise exercised by
  the existing two schemas) and drops `msisdn`/`regionCode`/`recordId`, matching this test
  case's own field list exactly.
* **A literal double-hyphen inside a draft comment closed the ASN.1 comment early, live and
  reproducible.** While drafting `gsm_cdr.asn`'s own header comment (ironically, while
  writing the warning *about* this exact pitfall, already flagged once in `telecom_cdr.asn`'s
  own comment), a `") -- a small GSM..."` fragment's mid-line `--` closed the comment right
  there, leaving `a small GSM call-detail-record SEQUENCE` as unparsed ASN.1 syntax --
  `pyparsing.exceptions.ParseSyntaxException: Expected Type, found 'small'`. Caught by
  actually running `asn1tools.compile_files(...)` locally against the file before wiring it
  into a spec (see below), not by inspection.
* **All 3 fixtures are valid** (unlike `docs/13`'s deliberately mixed batch) because this
  scenario's own "Expected Output & Verification Logic" is specifically "decoded
  imsi/call_duration_sec populated, zero decode-error rows" -- a clean-decode assertion, not
  a quarantine-routing one. The decode-failure path is already real, tested code
  (`docs/13_asn1_dq_quarantine.md`'s `cdr_005.ber`), so this scenario doesn't need to
  duplicate it.

## Error handling

`Asn1DecodeError` if `gsm_cdr.asn` itself is malformed or `asn1_pdu_name` doesn't resolve to
a `SEQUENCE` in it (validated once, onboarding-adjacent, via `derive_asn1_field_defs`);
per-record decode failures are captured inline as `_asn1_decode_error` (never raised), so one
malformed file wouldn't abort the batch -- not exercised by this scenario's own fixture set
(see `docs/13_asn1_dq_quarantine.md`'s `cdr_005.ber` for that path), but structurally covered
by the `dq_asn1_decode_ok` rule regardless.

## Extension points

Add a 4th CDR file (e.g. a deliberately malformed one, mirroring `docs/13`'s `cdr_005.ber`)
to `notebooks/00_seed_sample_data/03_seed_asn1_gsm_cdr_fixture.py` to additionally exercise
the decode-failure/quarantine path against this same `gsm_cdr.asn` schema -- no spec change
needed, the 3 quarantine rules already cover it.

## Real gaps / judgment calls made building this scenario

* **No pre-existing ASN.1 fixture matched this test case's own field list**
  (`imsi`/`imei`/`callDurationSeconds`/`cellId`/`roamingFlag`) -- the two schemas already in
  `sample_data/asn1_schema/` (`telecom_cdr.asn`/`telecom_cdr_v2.asn`) are missing `imei` and
  `roamingFlag` and carry `msisdn`/`regionCode` instead, so a genuinely new `.asn` module and
  fixture set were built (verified via a real local `asn1tools` compile/encode/decode
  round-trip and the framework's own `derive_asn1_field_defs`, not just written by hand and
  assumed correct).
* **A brand-new seed notebook**
  (`notebooks/00_seed_sample_data/03_seed_asn1_gsm_cdr_fixture.py`), rather than extending
  `02_seed_flowx_testing_data.py` -- that notebook is explicitly scoped (per its own
  header) to specs `001`/`002`/`003`, and this scenario's binary-fixture-generation-on-cluster
  requirement (see `docs/13`'s identical rationale) is self-contained and unrelated to the
  EA/Excalibur fixtures it already provisions.
* **`cdc_load_strategy: "APPEND"`, not a CDC-dispatched strategy** -- a raw telecom CDR event
  stream has no natural per-call update/merge key, so `SCD1`/etc. would be a poor fit; this
  wasn't specified explicitly in the test case detail, a reasonable default for "streaming
  telecom CDR ingestion" was chosen instead.
